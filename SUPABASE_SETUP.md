# Supabase and Google OAuth setup

## 1. Create the Supabase project

1. Create a new Supabase project at https://supabase.com.
2. Open the SQL editor and run the contents of [supabase/schema.sql](supabase/schema.sql).
3. In Project Settings > API Keys, copy:
   - Project URL
   - Publishable key (`sb_publishable_...`)
   - Do not use the secret key (`sb_secret_...`) in the Expo app; it bypasses RLS and must remain server-side.
4. Add the variables to your Expo environment:

```bash
cp .env.example .env
```

Then fill in:

```env
EXPO_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_<key>
EXPO_PUBLIC_REDIRECT_SCHEME=moneytracker
```

## 2. Configure Google OAuth in Supabase

1. In Supabase, open Authentication > Providers.
2. Enable Google.
3. Add the Google **Web application** OAuth client ID and client secret from Google Cloud.

## 3. Configure Google Cloud

1. Open Google Cloud Console > Google Auth Platform > Clients and create an OAuth client with application type **Web application**.
2. In Authorized redirect URIs, add the Supabase callback shown on Authentication > Providers > Google. It has this shape:

```text
https://<project-ref>.supabase.co/auth/v1/callback
```

3. Copy the client ID and secret into Supabase Authentication > Providers > Google. Keep the secret in Supabase; never put it in the app or `.env`.

## 4. Allow the app redirect in Supabase

In Supabase Authentication > URL Configuration > Redirect URLs, allow the app callback:

- Development/standalone build: `moneytracker://auth/callback`
- Expo Go: allow the exact redirect URI generated by `makeRedirectUri()` in that running Expo Go session.

Google redirects to Supabase's `/auth/v1/callback`; Supabase then redirects to the app callback. These are different URLs and belong in the Google and Supabase allowlists respectively.

## 5. App flow

The app opens Supabase's Google OAuth URL in the system authentication browser, receives a PKCE authorization code at the app callback, and exchanges that code for a Supabase session. The code is ready once the environment variables and dashboard redirects are configured.

## 6. Manual testing checklist

- Google sign-in works on a real device or simulator.
- Session persists after reload.
- Notes and entries stay isolated per user.
- Pending and paid flows update totals correctly.
- UPI app opening behaves correctly on Android/iOS.
- User confirmation is required before marking an entry as paid.
